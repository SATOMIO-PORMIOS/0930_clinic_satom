実装仕様

現在の佐藤医院 Webサイトを構成するページ、ファイル、共通機能と予約フォームの動作をまとめています。記載内容は現在の HTML・CSS・JavaScript の実装に基づきます。

1. システム概要

  • 静的な HTML ページで構成し、共通スタイルは assets/css/style.css にまとめる。
  • 共通の画面操作は assets/js/main.js、予約フォーム固有の操作は assets/js/reservation.js が担当する。
  • Google Fonts の Zen Maru Gothic を使用する。外部の予約 API やサーバー処理は実装していない。
  • サイト上の医院、人物、連絡先、住所は教材用の架空データとして扱う。

4. 共通 UI と動作

  • 見た目は assets/css/style.css、共通の操作は assets/js/main.js が担当する。
  • JavaScript はページ内に対象の要素がある場合に処理を設定する。以下に各機能の適用ページと動作を記載する。

4-1. メインナビゲーション

対象：トップページ・予約ページ。お知らせ、診療内容、当院について、診療時間・診療科目、アクセス、よくあるご質問の6項目を表示する。Web予約への入口はトップページの「Web予約フォーム」ボタンに設ける。

操作・条件表示・動作
幅が1000pxを超える画面緑の横並びメニューと葉の区切りを表示。項目にマウスを合わせる、または内部のリンクにキーボードフォーカスを移すと、詳細リンクのドロップダウンを表示する。
幅が1000px以下の画面メニューボタンでメニューを開閉する。ドロップダウンは非表示になり、各項目の主リンクから移動する。
メニューボタンを押すis-open を切り替える。ボタンの aria-expanded と「メニューを開く／閉じる」の名前も更新する。
メニュー内のリンクを押すリンク先へ移動し、開いていたメニューを閉じる。予約ページからトップの各セクションへは index.html#対象ID で移動する。
トップページをスクロールヒーロー下端が画面上端に達すると is-fixed を付け、ナビゲーションを固定する。ヒーローが見える位置へ戻ると解除する。予約ページではこのスクロール固定処理を行わない。
トップページをスクロール・リサイズページ内リンクの対象セクションを調べ、現在位置に対応するリンクを黄色と下線で強調する。選択リンクには aria-current="location" を付ける。

現在位置の判定には、画面上端から高さの35%の位置と固定ナビ下端を比較した基準位置を使う。その位置を通過したセクションのうち、上端が最も近いものを選択する。

4-2. パンくず・フッター・ページトップボタン

  • パンくずはトップ以外のサイト各ページに表示する。葉のアイコン、「ホーム」へのリンク、区切り記号、現在のページ名を並べ、サブカラーの背景と白文字で表示する。
  • サイト全7ページのフッターには、トップへ戻るロゴ、医院のキャッチコピー、電話番号・FAX・メール、教材用サイトの注意書き、著作権表記を配置する。
  • ページトップボタンはスクロール量が 400px を超えると表示し、400px以下になると隠す。
  • ボタンを押すとページの最上部へ滑らかに移動する。端末で動きを減らす設定が有効な場合は、滑らかな移動を使わずに戻る。

4-3. FAQ の開閉

対象：よくあるご質問ページ。

  • 初期状態では回答を hidden 属性で隠す。質問は通常のボタンとして、クリックやキーボードで操作できる。
  • 質問を押すと、aria-controls が指す回答の表示・非表示を切り替え、aria-expanded を更新する。
  • 質問ごとに独立して開閉するため、複数の回答を同時に表示できる。

4-4. 診療時間表と現在の受付状態

対象：トップページのヒーロー内の診療時間表。ブラウザーの現在時刻を Asia/Tokyo として取得し、読み込み時と60秒ごとに当日の曜日列・状態表示を更新する。

判定順条件（開始時刻を含み、終了時刻を含まない）表示
1木曜・日曜、または土曜12:00以降本日は休診日です
2上記以外で、受付中かつ診療開始前（8:00〜9:00、または土曜以外の12:00〜13:00）受付中です（診療は9:00から）／受付中です（午後の診療は13:00から）
3上記以外で、9:00〜11:00または13:00〜17:00現在：診療中です（受付中）
4上記以外で、9:00〜12:00または13:00〜18:00診療中ですが受付は終了しました
5いずれにも該当しない診療時間外です

休診・受付終了・時間外の場合は赤色の表示と「Web予約をご利用ください」のリンクを追加する。当日の曜日列には is-today を付ける。

診療開始前は受付中であることと診療開始時刻を表示する。休診日の判定を優先するため、木曜・日曜と土曜午後には受付中と表示しない。祝日・臨時休診・お知らせ本文とは連動していない。

4-5. 診療内容・スタッフ紹介のカルーセル

対象：トップページの診療内容カードとスタッフ紹介カード。画面幅が 480px 以下の場合に、カードを横へスクロールできる表示にする。

  • カードが2枚以上ある場合、カード数に応じた切り替え用ドットボタンを JavaScript で作成する。
  • スワイプや横スクロールでカードを移動できる。ドットを押すと対応するカードの左端へスクロールする。
  • スクロール位置から現在のカードを判定し、ドットの強調表示と aria-current を更新する。「何枚目／全何枚」の情報を支援技術向けに通知する。
  • 480pxの境界をまたいで表示を切り替えると、横スクロール位置を先頭へ戻す。自動送りは行わない。
  • 動きを減らす設定では、ドットによる切り替え時の滑らかなスクロールを使わない。

4-6. 電話・地図・予約へのリンク

  • tel: リンクを押すと「電話をかけますか？」の確認を表示する。キャンセルすると移動を止め、承認すると端末側の電話機能へ処理を渡す。
  • トップページと所在地ページの地図画像は、Google マップの「東京都台東区東上野3-35-9」の検索を新しいタブで開く。リンクには rel="noopener noreferrer" を指定する。
  • 地図にカーソルを合わせると、ブラウザーの標準ツールチップで「クリックでGoogleMapを表示」と案内する。
  • ページ上の表示住所は「東京都台東区上野0-0-0」。地図リンク用の仮住所とは別に管理する。
  • トップの「Web予約フォーム」と診療状況に表示される予約リンクは reservation.html へ移動する。予約フォームの詳細は次章を参照する。

5. 予約フォーム仕様

入力項目

  • 受診区分（初診・再診）、診療内容、氏名、ふりがな、生年月日、電話番号、メールアドレス、第1希望日・時間、個人情報の取り扱いへの同意は必須。
  • 再診を選ぶと診察券番号が表示される。診療内容で予防接種または健康診断を選ぶと、それぞれの詳細入力欄が表示される。
  • 第2希望日・時間、症状・相談内容は任意。相談内容は最大500文字で、文字数を表示する。

入力検証と日時候補

  • 必須入力とブラウザー標準の形式検証を行い、エラー時は該当欄に説明を表示して最初のエラー欄へフォーカスする。
  • 希望日は当日以降。木曜・日曜は選べず、土曜は午前の時間帯だけ候補にする。
  • 第1希望時間は必須。第2希望は未入力のままでも進める。
  • 現在の JavaScript では祝日や医院の臨時休診日は判定しない。

画面遷移

  1. 入力画面で検証に通ると、入力フォームを隠して確認表を表示する。
  2. 「入力内容を修正する」で入力画面へ戻る。
  3. 「予約を申し込む」で完了表示へ移り、ステップ表示を完了にする。

完了画面はブラウザー内のサンプル遷移です。入力内容の送信、保存、予約登録、医院からの連絡は発生しません。氏名・連絡先・生年月日などの入力を求める実運用には、送信先、個人情報の取扱い、セキュリティを別途設計する必要があります。

6. 画面幅への対応

  • 主な CSS ブレークポイントは 1200px、1000px、768px、480px。
  • 予約フォームは広い画面で2列、768px 以下で1列にする。
  • 小さい画面ではナビゲーションを開閉式にし、予約操作ボタンを横幅いっぱいにする。
  • 狭い画面では確認表の見出しと値を縦に並べる。

7. 現状と制約

  • 予約ページは静的なデモで、バックエンド、データベース、メール送信、予約枠管理を備えていない。
  • 予約完了表示は申込データが医院へ届いたことを意味しない。
  • 予約フォームの日時制限は曜日ベースのみで、祝日・臨時休診・実際の空き枠とは連動しない。
  • 住所・電話番号・診療情報は教材用の架空データである。

8. 変更時の確認事項

  • 共通ナビゲーションやフッターの変更は、トップページとサブページで表示が揃うよう反映する。
  • 予約項目を変更するときは、HTML の入力名、JavaScript の検証・確認表、説明文を合わせて更新する。
  • 曜日や診療時間を変更するときは、トップの診療表示、診療時間ページ、予約日時制限、お知らせの整合性を確認する。
  • 新しい CSS は共通部品なら style.css、予約ページ専用なら reservation.css に記述する。
  • 実送信機能を追加する場合は、画面上の完了表示だけでなくサーバー側の検証・保存・通知・個人情報保護まで設計する。
